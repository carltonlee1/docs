## Overview

Pathfinder provides full compatibility with the OpenAI Chat Completions API. You can use your existing OpenAI SDK code with minimal changes - just update the base URL.

Pathfinder accepts OpenAI-format requests and returns OpenAI-format responses. This means:
- Existing OpenAI SDK code works unchanged
- Standard parameters like `temperature`, `max_tokens`, `top_p` are supported
- Response structure matches OpenAI exactly
- Additional `pathfinder` metadata is included (ignored by SDKs)

## Base URL Configuration

Replace the OpenAI base URL with Pathfinder:

| Environment | Base URL |
|-------------|----------|
| Production | `https://api.pathfinder.naivana.io/v1` |
| Development | `https://api.dev.pathfinder.naivana.io/v1` |

## Code Examples

### Python (OpenAI SDK)

```python
from openai import OpenAI

# Simply change the base_url
client = OpenAI(
    api_key="pk_live_your-key-here",
    base_url="https://api.pathfinder.naivana.io/v1"
)

# Use exactly as you would with OpenAI
response = client.chat.completions.create(
    model="gpt-5.1",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Hello!"}
    ],
    temperature=0.7,
    max_tokens=100
)

print(response.choices[0].message.content)
```

### JavaScript (OpenAI SDK)

```javascript
import OpenAI from 'openai';

const client = new OpenAI({
  apiKey: 'pk_live_your-key-here',
  baseURL: 'https://api.pathfinder.naivana.io/v1'
});

const response = await client.chat.completions.create({
  model: 'gpt-5.1',
  messages: [
    { role: 'system', content: 'You are a helpful assistant.' },
    { role: 'user', content: 'Hello!' }
  ],
  temperature: 0.7,
  max_tokens: 100
});

console.log(response.choices[0].message.content);
```

### cURL

```bash
curl -X POST https://api.pathfinder.naivana.io/v1/chat/completions \
  -H "Authorization: Bearer pk_live_your-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.1",
    "messages": [
      {"role": "system", "content": "You are a helpful assistant."},
      {"role": "user", "content": "Hello!"}
    ],
    "temperature": 0.7,
    "max_tokens": 100
  }'
```

## Request Format

### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `model` | string | Model identifier (e.g., `gpt-5.1`, `claude-haiku-4-5`, `auto`) |
| `messages` | array | Array of message objects |

### Message Object

```json
{
  "role": "user" | "assistant" | "system",
  "content": "Message text"
}
```

### Optional Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `temperature` | number | 1.0 | Sampling temperature (0.0 to 2.0) |
| `max_tokens` | integer | varies | Maximum tokens in response |
| `top_p` | number | 1.0 | Nucleus sampling parameter |
| `stop` | string/array | null | Stop sequences |
| `presence_penalty` | number | 0.0 | Presence penalty (-2.0 to 2.0) |
| `frequency_penalty` | number | 0.0 | Frequency penalty (-2.0 to 2.0) |
| `user` | string | null | Unique user identifier for tracking |
| `stream` | boolean | false | Enable streaming responses |

## Response Format

Pathfinder returns OpenAI-compatible responses with additional `pathfinder` metadata:

```json
{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "created": 1704067200,
  "model": "gpt-5.1",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 20,
    "completion_tokens": 10,
    "total_tokens": 30
  },
  "pathfinder": {
    "provider": "openai",
    "cost_usd": 0.00012,
    "routing_decision_id": "rd_xyz789",
    "routing_latency_ms": 5,
    "completion_latency_ms": 450
  }
}
```

The `pathfinder` object is additional metadata - OpenAI SDKs will ignore it, so your existing code continues to work.

## Multi-Turn Conversations

Pathfinder fully supports multi-turn conversations:

```python
response = client.chat.completions.create(
    model="gpt-5.1",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "My name is Alice."},
        {"role": "assistant", "content": "Nice to meet you, Alice!"},
        {"role": "user", "content": "What is my name?"}
    ]
)
# Response will remember context from earlier messages
```

## Supported Models

You can use any of these models as drop-in replacements:

| Model | Provider | Best For |
|-------|----------|----------|
| `gpt-5.1` | OpenAI | General purpose |
| `gpt-5.2` | OpenAI | Complex reasoning |
| `claude-haiku-4-5` | Anthropic | Fast, cost-effective |
| `claude-sonnet-4-5` | Anthropic | Balanced quality/cost |
| `claude-opus-4-5` | Anthropic | Highest quality |
| `gemini-2.5-flash` | Google | Fastest, cheapest |
| `gemini-2.5-pro` | Google | High quality |
| `gemini-3-flash` | Google | Fast, capable |
| `gemini-3-pro` | Google | Advanced reasoning |

Or use `model: "auto"` to let Pathfinder choose the optimal model. See [Auto Routing](/pathfinder/core-concepts/auto-routing).

## Using Other Providers

The same code works with any provider - Pathfinder handles the translation:

```python
# Use Claude models
response = client.chat.completions.create(
    model="claude-haiku-4-5",
    messages=[{"role": "user", "content": "Hello!"}]
)

# Use Gemini models
response = client.chat.completions.create(
    model="gemini-2.5-flash",
    messages=[{"role": "user", "content": "Hello!"}]
)
```

The response format is always OpenAI-compatible, regardless of which provider actually serves the request.

## Stop Sequences

Control where the model stops generating:

```python
response = client.chat.completions.create(
    model="gpt-5.1",
    messages=[{"role": "user", "content": "Count from 1 to 10"}],
    stop=["5"]  # Stop when "5" is generated
)
```

## Temperature Control

Adjust randomness in responses:

```python
# Deterministic response (always same answer)
response = client.chat.completions.create(
    model="gpt-5.1",
    messages=[{"role": "user", "content": "What is 2+2?"}],
    temperature=0.0
)

# Creative response (more variation)
response = client.chat.completions.create(
    model="gpt-5.1",
    messages=[{"role": "user", "content": "Write a poem"}],
    temperature=1.5
)
```

## Streaming

Enable streaming for real-time responses:

```python
stream = client.chat.completions.create(
    model="gpt-5.1",
    messages=[{"role": "user", "content": "Tell me a story"}],
    stream=True
)

for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")
```

See [Streaming](/pathfinder/endpoints/streaming) for complete streaming documentation.

## Pathfinder-Specific Features

While maintaining OpenAI compatibility, you can also use Pathfinder-specific features:

```python
# Use auto routing
response = client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "Hello!"}]
)

# Access Pathfinder metadata from raw response
raw = response.model_dump()
print(f"Provider: {raw['pathfinder']['provider']}")
print(f"Cost: ${raw['pathfinder']['cost_usd']:.6f}")
```

See [Pathfinder Metadata](/pathfinder/core-concepts/pathfinder-metadata) for details on the additional fields.

## Migration Checklist

To migrate from direct OpenAI API:

1. Update base URL to Pathfinder endpoint
2. Replace OpenAI API key with Pathfinder API key (format: `pk_live_` or `pk_test_`)
3. (Optional) Change `model` to `auto` for intelligent routing
4. (Optional) Add `routing` parameter for cost/quality control

That's it - your existing code works unchanged.
